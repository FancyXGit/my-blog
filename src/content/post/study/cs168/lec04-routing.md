## 域内与域间路由

路由协议是指在网络中传输数据包时，确定数据包从源主机到目的主机的路径的规则和算法  
因特网是网络的网络，由许多局部网络构成。这些局部网络内部可以使用各自不同的路由协议。局部网络之间的路由协议需要统一，因为需要让数据包跨越不同的局部网络传输。根据路由协议的使用范围，路由可以分为两类：

- 域内路由协议(**intra**-domain routing protocol)或内部网关协议(**Interior** Gateway Protocol, IGP)：用于局部网络内部的路由协议。具体例子包括OSPF(Open Shortest Path First)、RIP(Routing Information Protocol)、IS-IS(Intermediate System to Intermediate System)等
- 域间路由协议(**inter**-domain routing protocol)或外部网关协议(**Exterior** Gateway Protocol, EGP)：用于数据包跨越多个局部网络的路由协议。具体例子包括BGP(Border Gateway Protocol)。由于每个网络都需要同意使用同一种域间协议，所以只有一种BGP协议被广泛使用

下文讨论的主要是域内路由协议

## 局内路由建模

我们考虑如何规划一种域内路由协议，为了支持将数据包传递到网络中的任意主机。我们可以将网络建模为一个图，图中的方形例如R1, R2, R3表示路由器，圆形如A, B, C表示主机，边表示路由器之间的链路

![局部网络建模](/image/post/study/cs168/lec04/intra-domain-routing-model.webp)

我们以后只考虑数据包目的地为主机的情况，虽然实际上router也可以是合法的目的地  
设计路由协议的时候，需要注意以下几点

- 我们考虑的是router之间如何传递数据包，因此常常会忽略主机的存在，只考虑router之间的转发关系
- 由于router的关系常常变化，例如某一条链路坏了，或者路由器坏了，所以路由的拓扑也会变化，路由协议需要应对这种改变
- 路由本身没有全局视角，不知道整张图的构成，因此路由协议的设计应该是分布式的，在局部视角之下计算出自己的答案，然后所有路由器的答案组合起来就能得到全局的路由结果
- 上文讲过，路由应该是尽力而为的

## 路由表

路由算法其实计算的就是路由器收到数据包之后，接下来发往哪一个相邻的路由器的问题。发往的下一个路由器被成为下一跳(next hop)。对于每一个目的地(也就是终端)，每一个路由器都要记录一张转发表，当数据包到达时，根据转发表的内容，路由器就知道应该将数据包发往哪一个相邻的路由器

![转发表](/image/post/study/cs168/lec04/routing-table.webp)

通常来说，对于一个目的地，只能有一个特定的转发方向，也就是只有一个下一跳。但是一个相邻的路由器可以接受多个目的地的包  
通过写下每一个路由器的转发表，我们就得到了整个网络的路由状态。对于每个数据包，我们都确定了路由器会如何转发它  
物理世界中，路由表不是将目的地映射为相邻路由器的名字，而是映射到对应的路由器端口。例如端口1链接着路由器R1，那么发给R1的包就会被发往端口1。路由器本身不关系邻居路由器是啥，只关心发往哪个端口的线

![路由器端口](/image/post/study/cs168/lec04/router-port.webp)

:::note
注意路由(routing)和转发(forwarding)的区别

- 路由是指路由器之间彼此通信，计算出路由表的过程
- 转发是指路由器接受数据包之后，根据路由表的内容，将数据包发往下一跳的过程

:::

## 路由状态有效性

如何判断一个路由状态是否有效或者正确呢？一个有效的路由状态需要将任意目的地的数据包在有限时间之内转发到目的地中。为了判断路由状态是否有效，我们需要一个全局的图景，也就是整个网络中所有路由器的拓扑图，以及所有路由器的路由表的集合  
事实上，路由状态有效，必须满足两个条件，这两个条件是有效的充要条件

- 没有死路：一个数据包到达路由器之后，路由器不知道如何处理。数据包不会继续走到达目的地了
- 没有环：一个数据包在路由器之间循环转发，永远到达不了目的地

![死路](/image/post/study/cs168/lec04/dead-end.webp)
![环](/image/post/study/cs168/lec04/loop.webp)

这两个条件显然是必要的，现在证明充分性：如果一个路由状态没有死路也没有环，那么对于任意目的地的数据包，由于没有死路那么它到达目的地之前不会停止，而且没有环，因此他不会经过同一个路由器两次。由于网络中路由器的数量是有限的，因此数据包最终会到达目的地  

有了这两个条件之后，我们就可以判断一个路由状态是否有效了。具体是先单独考虑一个目的地，画出所有路由器的转发路径，判断是否有死路或者环。如果没有死路也没有环，那么这个目的地的路由状态是有效的。然后再考虑下一个目的地，重复上述过程，直到所有目的地都被考虑过了，那么整个网络的路由状态就是有效的  

![验证路由状态](/image/post/study/cs168/lec04/validate-routing-state.webp)

用图的术语说，满足上述条件的路由状态如果把转发关系画成箭头，那么就形成一个有向生成树，以目的地为根

## 最小化花费

现在我们定义了什么是有效的路由状态，也证明了什么条件可以使得一个路由图有效。但是一个图可能有多种正确的路由状态，这时候需要找到成本最低的路由状态  
我们给每一条链路定义一个成本，成本取决于链路的带宽、延迟、可靠性等因素，它表示有多希望使用这条链路。成本是非负的，成本越低表示越希望使用这条链路。允许成本的自定义，使得运营者可以根据自己的需要选择权重得出链路的成本  
由此，成本最低的路由状态就是指从每一个路由器到目的地的路径的总成本最小。在设计路由协议的时候，我们假定成本是现有的，我们无需考虑成本怎么来的

![路由成本图](/image/post/study/cs168/lec04/routing-cost.webp)

关于如何找到成本最低的路由状态，是我们需要重点讨论的问题，将会在下面几节详细阐述
